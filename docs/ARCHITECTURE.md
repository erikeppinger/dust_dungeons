# Architecture

```
lib/
├─ main.dart             entry point (ProviderScope)
├─ app/                  MaterialApp, navigation shell, theme
│  └─ theme/             Material 3 theme + ChorePalette (vibrant / Okabe-Ito)
├─ core/                 shared widgets, day clock (midnight/resume aware)
├─ data/
│  ├─ db/                Drift tables + AppDatabase (schema version, migrations, seeding)
│  ├─ models/            plain data classes (AppSettings)
│  ├─ repositories/      chores, progress (completions + point ledger), settings
│  └─ providers.dart     Riverpod providers wiring database → repositories → UI streams
├─ domain/               pure Dart: dates, recurrence engine, points & bonuses, streaks & levels, fights (domain/fight/)
├─ game/                 generated from game/*.toml by tool/build_game_data.py (catalog and text lookups)
├─ features/<feature>/   screens + Riverpod controllers per feature
└─ l10n/                 ARB source files (generated Dart files are git-ignored)
```

## Principles
- **`domain/` is pure Dart** with no Flutter imports, so it can be unit-tested in isolation.
- **State:** Riverpod `Notifier`s per feature, and widgets only read providers.
- **Persistence:** local SQLite via Drift. Points are an append-only ledger: undo marks the completion `undoneAt` and books a negative entry instead of deleting anything. "Due" dates (0.2) will be computed rather than stored.
- **Layering:** `features` → `data` → `domain`. `data` never imports `features`.
- **Built-in chores** are identified by a stable `seedKey` and get localized titles. Missing ones are inserted on every start (`insertOrIgnore`), so new built-ins arrive with updates without touching user edits.
- **Schedules:** `Recurrence` (domain) computes due dates. Fixed schedules split time into cycles that start at each occurrence, and one completion covers its cycle. "N days after last done" floats with the last completion. Nothing about "due" is stored: it is derived from the schedule, the last completion and today (`ScheduledChore`).
- **Points:** `pointsFor()` (domain) is the single rule. The repository applies it when a chore is completed, and the Today tiles use it to preview. The awarded total is stored per completion, and undo books exactly that back. XP is the sum of all awarded points, so spending (0.5) will not lower the level.
- **Notifications:** `planNotifications()` is pure: given chores, completions, settings and "now", it returns every notification for the next 7 days, fully worded. `notificationPlanProvider` rebuilds the plan on any change, and `syncNotifications()` applies it through `NotificationService` (one update at a time, newest wins). The platform plugin sits behind that interface, so tests use a fake.
- **Boss fights:** `lib/domain/fight/` holds the rules (families, patterns, judging, health) as pure Dart. `FightProgress` derives tokens, wins and tiers from completions and the `Fights` table, like the point ledger. `FightController` runs a duel in real time on `clock` and timers, and screens only render it. Sounds sit behind `FightSounds` (silent in tests).
- **Game data:** items, bosses, built-in quests and balance numbers are TOML files in `game/` (see `game/README.md`). `tool/build_game_data.py` checks them against `game/schema/` and the code's enums, and generates `lib/game/game_data.dart` (constants read by the domain code), `lib/game/game_texts.dart` (name, title and icon lookups) and the generated entries of the ARB files (marked in their `@` metadata). Its `--check` mode runs in `test/game_data_test.dart`, and `game/keys.lock` keeps stored keys from disappearing. Item descriptions are composed at runtime from the effects (`items_text.dart`). Difficulty presets (`lib/domain/fight/difficulty.dart`) scale boss health, timing and tempo in `EchoDuel`.
- **Hero art:** `HeroArt` paints `assets/art/hero/hero.png` with the Wardrobe colors swapped in (`heroColors`), then the worn gear's layers from `assets/art/hero/wear/` in the order of `wearLayers` (`items.dart`). The map's tiny hero is still drawn in code. `BossArt` paints a frame of `assets/art/bosses/<family>.png`; quest icons are `Sprite`s too (`chore_icons.dart`, also painted into the home widget).
- **Fight rounds:** `FightController` waits in `FightStage.ready` for the start button (`go()`) before every round; `playheadMs` and `taps` feed the `BeatTimeline`. `EchoDuel.applyEcho` judges a round as a whole: it lands at `roundsHitPercent` accuracy or more (damage), or fails (no damage, one heart through `_heartDue`, where shields and the Garden Gnome act). The lane phase uses `applyHits`, note by note.
- **Shop and gear:** `lib/domain/fight/shop.dart` defines `ShopItem`; the catalog itself is generated (Armory gear, loot, consumables, hats, vouchers). `ShopRepository.buy` checks the balance, books a `spend` ledger entry and updates `Inventory` in one transaction. XP is derived from completions, so spending never lowers it. Worn gear lives in `Equipped` (one item per slot). `lib/domain/fight/items.dart` turns gear, picked consumables and a curse into `Effects` through a `Loadout`, which the duel reads; it also holds the loot roll and the curses. `FightRepository.finish` rolls loot (seeded by the fight's id) and sets the curse in the same transaction as the result; `start` uses the curse up, and a completion of the cursing family lifts it (`ProgressRepository.complete`).
- **Boss forms:** `bossForm(family, tier)` (from `game/bosses.toml`) gives a chore boss's colors and `BossTrait` at tier 2 and 3. `EchoDuel.styleOf` and `extraBeats` apply the trait; `BossArt(tier:)` swaps the boss's four palette colors and paints the overlay from `assets/art/bosses/forms`. Built-in quests marked `suggested` are inserted archived (`SeedChore.suggestion`); `sleepingBosses` in `lib/features/world/sleeping_bosses.dart` decides which bosses sleep in the Arena.
- **Weekly Overlord:** a ninth `BossFamily` value fed by no chore (`choreFamilies` lists the others). `FightProgress` derives weekly wins from the fight history. `OverlordDuel` extends `EchoDuel` with a lane phase driven by `FightController`. Its look, name and trait come from the week (`OverlordLook.forWeek` in `lib/domain/fight/overlord.dart`, from `game/overlords.toml`); the look is stored with each Overlord fight (`fights.look`), and `OverlordArt` stacks and recolors its parts.
- **Accessibility audit:** `test/accessibility_test.dart` runs Flutter's tap-target, label and contrast guidelines on every main screen (light/dark, both palettes) and lays them out at 200 % font size in English and German. New screens should be added there.
- **Onboarding:** `AppSettings.onboardingDone` picks the home route. `SettingsRepository.load` treats a missing flag as done when completions exist (installs from before 0.6).
- **Weekly quest map:** `lib/domain/fight/overworld.dart` generates a `WeekMap` (terrain, route, road, theme) from the ISO week alone, as a window onto one endless noise field. `joinWeeks` links each castle to the next camp across the seam. There is no storage, so past weeks can be redrawn for a future world view. `quest_map.dart` paints it from 16×16 tile sprites in the season's palette, and joins roads, shores and fog in code.
- **Profiles:** everything per person watches `currentProfileIdProvider`, a notifier remembered on the phone under a setting a merge never takes over. Switching rebuilds every per-person screen. `profilesProvider` comes preloaded at startup, so the first frame never waits. Who sees a chore, and when it's due, is the pure `schedule()` in `scheduled_chore.dart`. It works from completions per (chore, person): anyone's chores use the household's latest, personal ones (`Assignment.one`/`each`, people in `chore_assignees`) their person's. `householdScheduleProvider` (everyone's chores) feeds notifications. Screen time is active only with one person (`screenTimeActiveProvider`). Design: [design/profiles.md](design/profiles.md).
- **Schedules:** `Recurrence` (domain) also covers monthly-on-a-weekday (`monthWeek`) and day windows (`windowDays`, with `windowEnd` capping before the next occurrence). Times of day are a `TimeWindow` on the chore. `ScheduledChore` derives open / overdue / later today / time's up from the window and `nowProvider`, a clock that ticks each minute and is fixed in tests, and `isOnTimeNow` is the one on-time rule for points. Design: [design/scheduling.md](design/scheduling.md).
- **Home screen widgets:** `widgetQuests` (pure) picks the quests per day, and `WidgetArt` draws each of the three `WidgetStyle`s as a PNG with `dart:ui`: the pixel font, the quest icon sprites and the coin sprite, in the app's day and night themes. `syncHomeWidget` asks Android which styles are placed (`home_widget` channel) and draws only those, day and night, for 7 days, into `files/widget/<style>-<day|night>-<date>.png`. It then asks Android to refresh. Kotlin `QuestWidget` (one subclass per style) shows the picture for today and the current mode.
- **Backups:** `lib/data/backup/` is plain Dart. `writeSnapshot` (`VACUUM INTO`) and `checkBackup` (`sqlite3`, read-only) cover files, and `restoreSnapshot` undoes an import in place (ATTACH and copy). `mergeBackup` adds a backup's history by meaning rather than ID, and its preview is the same merge rolled back. `features/backup/` holds the `Backups` actions, the daily schedule (`scheduleAutoBackups`) and the page. The pickers and folder writes sit behind `BackupService` (Kotlin `Backup.kt`, Storage Access Framework), with a fake in tests. Design: [design/data-safety.md](design/data-safety.md).
- **Schema changes:** bump `schemaVersion` in `app_database.dart`, add a migration step, run `dart run build_runner build`, dump the new schema (`dart run drift_dev schema dump lib/data/db/app_database.dart drift_schemas/`), regenerate test helpers (`dart run drift_dev schema generate drift_schemas/ test/data/generated_migrations/`) and extend `test/data/migration_test.dart`. Generated files and schema dumps are committed.
- **Theming:** chore colors come from the `ChorePalette` theme extension, never hard-coded colors. `app_theme.dart` builds the 16-bit look (day/night `ColorScheme`s, pixel font headings, `PixelBorder` frames), and `PixelColors` carries the day or night UI palette.
- **Pixel art:** PNGs and `.gpl` palettes in `assets/art` are the source; `tool/build_art.py` checks them and generates `lib/app/art/art_data.dart` (palettes and sprites as constants). `Sprite.paint` draws a sprite in any palette of its group, so seasons and day/night are palette swaps. `test/art_test.dart` fails when the generated file is stale. See [ART_GUIDE.md](ART_GUIDE.md) and [design/art-assets.md](design/art-assets.md).
- **Localization:** `AppLocalizations.of(context)`, generated from `lib/l10n/*.arb` on `flutter pub get`.
- **Privacy:** the main `AndroidManifest.xml` removes `INTERNET` from all merged manifests.
